* Introduction
People have different opinions on what are "overlay", "fzozen"
etc. merges and what was really implemented in lispmds, also their
opinions change depending on their current work. To avoid infinite
discussions and renaming, merge types are now just numbered.

See also [[https://github.com/acorg/acmacs.r/issues/5][github issue]]

* Merge type 1
Tables are merged. Projections in the source charts are ignored. The
merge has *no projections*.

* Merge type 2
Tables are merged. The best projection of the first chart is
copied. Projections of the second chart are ignored. Coordinates of
non-commong points of the second chart are set to NaN. The merge has
just one projection. If the first chart has no projections, error is
raised. Resulting projection is *not relaxed*.

relax_incremental() can be used to relax the merge.

If you want to freeze primary map (projection of the first chart in
the merge) and randomize and relax just points found in the secondary
table (merged in), use 
relax_incremental(number_of_optimizations, "unmovable-primary-points")

* Merge type 3
Tables are merged. The best projection of the second chart orieneted
to the best projection of the first chart using procrustes.
Coordinates of the non-common points are copied to the resulting
layout from their source layouts. Coordinates of each common point are
set to the middle between coordinates of that point in the source
projections. Resulting projection is *not relaxed*.

* Merge type 4
Merge type 3 is performed. Then the points of the first chart
(including common points) are fixed and the merge is *relaxed*,
i.e. points found only in the second chart are allowed to move.

* Merge type 5
Tables are merged. The best projection of the second chart orieneted
to the best projection of the first chart using procrustes.
Coordinates of all points of the first chart and coordinates of
the non-common points of the second chart are copied to the resulting
layout from their source layouts. Then the points of the first chart
(including common points) are fixed and the merge is *relaxed*,
i.e. points found only in the second chart are allowed to move.

* Across-layer titer combination (the titer table merge)

The merge types above concern *projection* handling. Independently, whenever a merge
produces a *layered* table (any merge stacks the source tables as layers), each
antigen×serum cell's titer is combined *across the layers* by the lispmds algorithm
(=Titers::merge_titers=, steps 1–9). The steps, verbatim from the code:

: 1. If there are > and < titers, result is *
: 2. If there are just *, result is *
: 3. If there are just thresholded titers, result is min (<) or max (>) of them
: 4. Convert > and < titers to their next values, i.e. <40 to 20, >10240 to 20480
: 5. Compute SD, if SD > limit, result is *
: 6. If there are no < nor >, result is mean of log titers.
: 7..9. thresholded/regular reconciliation

** Rule 5 — the SD gate, and its two knobs

Rule 5 drops a cell to =*= when the standard deviation of its across-layer log2 titers
exceeds a limit. Its purpose is real: a cell titrated e.g. 40 and 320 for the same
antigen×serum is an inconsistent repeat, and averaging it launders a titration
disagreement into a confident-looking titer. Two parameters control it:

- =sd_limit= — the SD ceiling (log2 scale). =NaN= disables the gate (rule 5 skipped).
- =sd_denominator= — the SD denominator: =population= (÷n, as the legacy AD toolkit
  =acmacs-chart-2=) or =sample= (÷(n−1), R's =sd()= / Racmacs). Sample SD is larger, so
  at a common limit it drops *more* cells; the two differ only near the boundary.

** Context-dependent defaults

The Python merge API (=ae_backend.chart_v3.merge=, and the =ae.chart.merge= wrapper)
resolves the pair of options as follows — the observable behaviour is exactly:

| =sd_limit= supplied? | =sd_denominator= supplied? | effective threshold | effective denominator |
|----------------------+----------------------------+---------------------+-----------------------|
| no                   | no                         | 1.0                 | population ← AD parity |
| yes                  | no                         | as given            | sample (Racmacs)      |
| no                   | yes                        | 1.0                 | as given              |
| yes                  | yes                        | as given            | as given              |

Rationale: leave both alone and you reproduce AD/lispmds exactly (population SD @ 1.0,
the hands-off default). The moment a caller sets a threshold they are tuning the gate,
so — absent an explicit denominator — the sample (n−1, Racmacs) denominator is used. An
explicit =sd_denominator= always wins. =sd_limit=float("nan")= still means "no gate".

The C++ =merge_settings_t= holds only the hands-off concrete defaults
(=sd_limit=1.0=, =sd_denominator=population=); the "threshold-supplied ⇒ sample"
fallback lives one layer up, in the pybind binding, which needs to know whether each kwarg
was actually passed. That resolution is factored into a single shared helper
(=resolve_sd_gate= in =cc/py/sd-gate.hh=) so every entry point applies the same matrix.

** Re-gating an already-merged chart in place

A merged chart keeps every source table as a layer, so the SD gate can be re-applied
without re-merging the source tables. =Chart.set_titers_from_layers(sd_limit=None,
sd_denominator=None)= recomputes the main titers in place from the layers using the same
rule 5 and the same defaults matrix as =merge= above (via the shared =resolve_sd_gate=
helper), and restores the forced column bases when the layers contain =>=-thresholded
titers. This makes =sd_limit= sweeps / sensitivity analyses instant. It raises if the chart
has fewer than two layers.
